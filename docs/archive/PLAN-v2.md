## 0. 已定的三件事（决策记录，2026-08-16 主人拍板）

初版计划在此处列了三个待决策项，主人已全部拍板。记录决定与理由，
细节落到对应章节。

### 决定 1：保留有条件出口的回边，"可出"必须被保证

主人原话的意思：前面的"有向无环"定义局限了一点，**有条件可出的环没问题，
但一定要保证可出，否则就是无限循环**。

落实为双保险（见 4.2）：

- **理论可出**：校验期断言每个环都存在条件出口（指向环外或终点），
  这条 v1 已实现（SCC 检测）；
- **实际必停**：条件出口无法静态保证模型一定会选它（模型可能永远判
  `repair`），所以 `max_iterations` 上限是**不可协商的第二道防线**，
  外加成本与墙钟兜底。

界面把回边画成虚线并标注轮数上限。

### 决定 2：密钥存储由实现者定，要求是安全

选定方案 A（继续用 `config/.env`）加三条加固（见 3.2）：
原子写、尽力收紧 Windows 文件 ACL、配置界面提供"测试连接"。
边界诚实标注（见第 7 节）：明文挡不住同用户身份的进程。

DPAPI（Windows 凭据管理器）不进本阶段：它挡得住"文件被拷走"，
挡不住本机 agent（同一用户身份可无阻碍解密），而前者和 gitignore +
备份纪律重叠。值得单独做，不塞进来。

### 决定 3：思考深度要做，但先探测能力；探测不到就不做本版本

主人的指示分两层：

1. **先判断有没有办法获取各家模型的思考深度参数。没有，本版本就不做。**
2. **有，则内部统一四档（低 / 中 / 高 / 极高），对各家实际可用参数做映射。**
   主人给的映射示例：只有低中高的，极高映射为高；只有开关的，
   低和中映射到关、高和极高映射到开。

完整设计见 4.1.1。已有的实测事实（Kiro 静默忽略 thinking 参数）说明
探测的判据不能是"参数被接受"，必须是"响应里真的出现思考内容"。

## 1. 实测事实（2026-08-16，本机）

这一节是下面所有设计的依据。**没有推测**。

### 1.1 五家供应商全部可以拉取模型列表

| 供应商 | 端点 | 状态 | 可见模型数 | 当前白名单数 |
|---|---|---|---|---|
| Deepseek | `/models`（OpenAI） | 200 | 2 | 2 |
| SuperAI | `/v1/models` | 200 | **20** | 7 |
| Kiro | `/v1/models` | 200 | **15** | 5 |
| Minimax | `/anthropic/v1/models` | 200 | **8** | 1 |
| RightCode | `/gemini/v1/models` | 200 | 5 | 3 |

**定位先说清楚：API 里可见的模型不等于要配置的模型。**
白名单本来就是**有意的选择**——只暴露你决定用的那部分，这不是缺口。
拉取的价值在于：把候选摆出来让选择变容易，以及免去"记模型名、抄错
模型名"这类手工增补的麻烦。

**结论：勾选式配置可做。** Deepseek 的 Anthropic 端点没有 `/models`（404），
所以探测要按"每个供应商各自能用的那个协议"来，不能假设两个都有。

### 1.2 思考深度参数的支持不一致

```
Deepseek deepseek-v4-pro（OpenAI 协议 reasoning_effort）
  不传        → reasoning_tokens=68
  low        → reasoning_tokens=64
  high       → reasoning_tokens=67
  非法值      → HTTP 400，明确列出合法取值   ← fail-closed，好

Kiro claude-sonnet-5（Anthropic 协议 thinking.budget_tokens）
  不传 / 1024 / 3000 → 三次都是 blocks=['text']，没有 thinking 块
                                                ← 静默忽略，危险
```

Deepseek 三档的 reasoning token 差异很小，是因为测试题太简单（"1 到 15 有几个质数"），
不足以区分档位——**这条只能说明参数被接受且被校验，不能说明档位真的改变了思考量**。
真正的档位效果需要用复杂任务重测，列入 M4 的验证项。

Kiro 那三行是硬结论：同一个参数三种取值，输出完全一致且无思考内容。

### 1.3 v1 的界面已经能用，问题在观感与信息密度

浏览器实测确认可用：图结构、节点定义、完整输入输出、实时事件流、批准按钮都工作。
不足是视觉层面（下文 M5）与长文本可读性（几万字符的投影现在是一个纯 `<pre>`）。

## 2. 我从两份调研里拿什么、不拿什么

调研了 dsh 的模型配置实现（约 2000 行前端 + 完整设计档案）和 Quorum 的节点参数设计
（含 837 行问题档案）。结论不是照搬，有几处我明确不同意。

### 2.1 直接采纳

| 来源 | 做法 | 为什么对 Atlas 成立 |
|---|---|---|
| dsh | **配置存引用名，不存密钥值** | `providers.json` 已经这么做了，继续 |
| dsh | **凭据的读接口在类型上没有 value 字段** | 不是"记得别返回"，是结构上没地方放。变成断言 A8 |
| dsh | **空输入框 = 保留原值**，纯空格 = 报错 | 一行代码解决"怎么编辑一个看不见的字段" |
| dsh | **拉取结果进选择器，已配置的默认不勾，用户改过的行赢** | 防止一次拉取覆盖手工调好的参数 |
| dsh | **协议白名单 + 明确的"不支持"** | 猜错响应格式和"该供应商没有模型"在界面上无法区分 |
| dsh | **命名了凭据却缺失就大声失败，绝不回退到环境里的其他 key** | 否则账单记到别人头上 |

| Quorum | **每节点一张参数表，不要批次共用** | 共用会让并行分支互相污染 |
| Quorum | **废弃字段显式报错，不静默接受** | |

### 2.2 我不照搬的三处

**① 不引入 Quorum 的 `mode` 轴。**
Quorum 用 `mode`（text/read/write）作为能力单轴。Atlas 的 `type`
（llm/research/coding_agent/human）已经承担了同一职责，而且语义更贴近使用者。
再加一个 `mode` 就是 Quorum 自己记录的教训："旋钮总数已达 32 个且全是机制级的"。
**Atlas 的节点参数要按意图建模，不按机制建模。**

**② taste skill 取纪律、不取清单，动效预算按 M5 的实际定位给足。**
taste 自己第 8 行写明："landing page、作品集、改版。**不是 dashboard，不是数据表格，
不是多步产品界面**。"所以它那套"英雄区不超过两行标题""禁止三栏等宽卡片"的
落地页规则对 Atlas 不适用，但高品质纪律全部适用：禁 AI 紫渐变、禁 Inter
作默认字体、数字用等宽、动效必须说得出理由、一个页面一套圆角、一个强调色
锁死全页、对比度过 WCAG AA、暗色从第一天做、`prefers-reduced-motion` 必须降级。
初版计划曾据此把动效压到 3/10——那是误用：taste 禁的是**无理由的**装饰动效，
不是动效本身。M5 的定位是"美观高级"（见第 5 节的判断修正记录），
动效预算给到 7/10，每一条都写明表达什么。

**③ 不做后台定时刷新模型目录。**
dsh 显式否决过，理由我认同：那会让模型列表变成需要缓存、失效策略和离线路径的
外部可变状态。拉取只在你点按钮时发生。

### 2.3 我要比它们做得更好的一处

Quorum 的问题档案里，最大的一族（A 族）是**"字段声明了但没有任何代码读它"**，
后果全部是静默的。它自己的结论是"逐个修不够，需要一条能机械检查的约束"，
但它至今只有逐个修。

Atlas 从这一阶段开始立一条规矩，写成断言 A9：

> **每一个可声明的节点参数，都必须配一个测试，断言它真的改变了发出去的请求或实际的执行行为。**
> 加参数不配这个测试，就不许合并。

这条规矩比任何具体参数都重要，因为它是"参数骗人"这一整类事故的机械化防线。

## 3. M3：模型与供应商配置界面

**目标：不打开任何文件就能配好供应商、勾选模型、填密钥。**

### 3.1 先划清一条新界线

界面此前是**纯只读**的。这一步第一次给它写权限，所以界线必须先说清楚：

> **界面可以改"环境"，不能改"图"。**
> 环境 = 供应商、模型清单、密钥、费率。
> 图 = 节点、边、prompt、consumes，仍然只能由 YAML 文件和 harness 里的 agent 改。

这条界线让红线①（不做任意代码节点）和你的"UI 编排推迟"两条都不受影响。

### 3.2 后端

- `atlas/credentials.py`（新）：读写 `config/.env`，三条加固（决定 2）：
  - **原子写**：先写临时文件再改名，写一半崩溃不会留下半份配置；
  - **尽力收紧 ACL**：写入后用 `icacls` 移除继承、只留当前用户（Windows 上
    没有 POSIX 的 0600，这是能做的最接近的事，失败不阻塞、记警告）；
  - 保留文件里已有的注释与键顺序，只动要改的行。
  读接口返回的类型里**没有 value 字段**，只有 `{configured, source, writable}`。
- `atlas/discovery.py`（新）：拉取模型列表。按 1.1 的实测结果，每个供应商用它自己
  能用的那个协议；不支持的返回明确的"请手填"，不猜格式。4MB 上限按实际字节算。
- `atlas/web.py`：新增配置端点。全部走 M1 已有的 Host 校验 + 写操作自定义头，
  并且额外**钉死 loopback**——拉取模型这个动作本质是"让本机向你指定的 URL 发请求"，
  这是一个探针，不能暴露给任何非本机调用方。
- 密钥写完立刻提供**"测试连接"**按钮（一次最小调用），失败原因直接显示，
  不让坏配置留到跑图时才炸。

### 3.3 界面

一个"设置 / 模型"页，与观测页并列：

- 供应商列表，每行：名称、协议、模型数、凭据状态圆点（三态：已配置 / 命名了但缺失 / 无需凭据）
- 点开编辑：base URL、协议、密钥输入框（placeholder 写"已配置，输入新值可替换"）
- **「从 API 拉取模型」按钮 → 勾选你决定用的 → 写回白名单。**
  拉取结果是**候选清单**，勾多少配多少；已配置的模型默认保持勾选，
  你手工改过的参数（如输出上限）在再次拉取时永远赢，不会被覆盖
- 不拉取也行：模型行支持手填（供应商没提供列表端点时的退路）
- 新建自定义供应商是**另一张卡片**，不复用编辑器（dsh 踩过的坑：编辑器按路径寻址，
  新建时路径还不存在，每次按键都会重建组件并丢草稿）

### 3.4 闸门

- **A8（新断言）：密钥永不出界。** 遍历所有 GET 端点的响应，断言其中不含任何
  密钥子串；并且在类型层面断言凭据视图没有 value 字段。
- 一次不打开文件的完整配置：加一个供应商 → 拉取模型 → 勾选 → 填密钥 → 跑通一张图。
- A1–A7 全部照旧通过。

## 4. M4：节点参数与图结构

**目标：节点能配到 Quorum 那种精细度，而且每个旋钮都验证过真的生效。**

### 4.1 新增的节点参数

按"意图"而不是"机制"命名。全部可选，不填就用现在的行为。

| 参数 | 适用类型 | 取值 | 说明 |
|---|---|---|---|
| `max_output_tokens` | llm | 正整数 | 现在只能按供应商配，下放到节点 |
| `thinking` | llm | `low` / `medium` / `high` / `xhigh` | 四档统一，按 4.1.1 的能力映射落地 |
| `temperature` | llm | 0–2 | |
| `seed` | llm | 整数 | 各家是否尊重未实测，列入本里程碑验证项 |
| `writable` | coding_agent | 布尔，默认 true | false 就是只读调研，且**不采集改动** |
| `allow_web` | research / coding_agent | 布尔 | |
| `allowed_paths` | research / coding_agent | 路径列表 | 隔离副本内的可读范围 |
| `timeout_s` | 全部 | 正整数 | 节点级覆盖 |
| `retry` | 全部 | 整数 | 同一模型内重试次数，与失败链是两件事 |

#### 4.1.1 思考深度：四档统一，按能力映射（决定 3 的落地）

各家模型对思考深度的定义不一样，有的有完整档位，有的只有开关，有的没有。
Atlas 对使用者只暴露**统一的四档**：`low / medium / high / xhigh`（低 / 中 / 高 / 极高），
内部把四档映射到各家实际支持的参数。

**第一步：能力探测（做不做的前提）。**

对每个模型发一次最小的探测调用（复杂度足以触发思考的题 + 显式思考参数），
判据**不是"参数被接受"**——Kiro 实测证明参数可以被静默吞掉——而是：

- OpenAI 协议：`usage.completion_tokens_details.reasoning_tokens > 0`；
- Anthropic 协议：响应 `content` 里真的出现 `thinking` 块。

探测结论按模型记入能力表（`config/capabilities.json`，可手动重测）。
**如果全部供应商的所有模型都探测不到真实的思考控制，本版本砍掉
`thinking` 参数并在 RESEARCH 里记录**——这是主人的原话，也是对的：
一个不生效的旋钮比没有旋钮更糟。

**第二步：映射规则。**

| 模型的实际能力 | low | medium | high | xhigh |
|---|---|---|---|---|
| OpenAI `reasoning_effort`（minimal/low/medium/high） | low | medium | high | **high** |
| Anthropic `thinking.budget_tokens`（数值预算） | 1k | 4k | 16k | 32k |
| 只有开关（enabled/disabled） | **off** | **off** | on | on |
| 无思考能力 | 置灰 | 置灰 | 置灰 | 置灰 |

budget_tokens 的具体数值是初值，M4 探测各家实际上限后修正。
主人给的两条示例（"只有低中高就把极高映射为高""只有开关就低中映射关、
高和极高映射开"）就是这张表的第二、三行。

**第三步：可见性（A10）。**

- 能力表标注每个模型支持到哪一档，界面的四档选择器据此置灰不可用的选项；
- 每次调用后核对：设了思考深度但响应里没有思考内容，记 `effort_ineffective`
  警告事件并显示在节点上——照 v1 处理"假成功"的同一套办法。

**每一个都要配一个 A9 测试**，断言它真的改变了发出去的请求体或子进程的命令行。

`writable: false` 的实现要照 Quorum 最狠的那一条：**不靠 CLI 配合，靠不采集**。
只读节点在副本里就算写了文件，引擎也不收集它的改动。理由是"如果命令行参数完全没生效，
这条约束还成立吗"——只有不采集这一条经得起这个提问。

### 4.2 图结构扩展

- 多入口（多个起点并行开跑）
- 扇入等待（一个节点等多个上游全部完成）
- 回边按决定 1 保留：**有条件出口的环是合法的**，界面画成虚线并标注轮数上限

**"可出"是双保险，缺一不可（决定 1 的核心关切）：**

1. **理论可出**（校验期，静态可验）：每个强连通分量至少有一条带 `when` 的
   出边指向环外或终点。v1 已实现，没有出口的环在校验期就拒收。
2. **实际必停**（运行期，不可协商）：条件出口没法保证模型一定会选它——
   模型可能连续十轮都判 `repair`。所以有环的图**必须**显式设 `max_iterations`
   （v1 已强制），外加成本与墙钟两道墙。任何一道触发都以 GuardViolation
   大声失败，不会安静地烧钱。

只有第 1 条的图论纯度是不够的，只有第 2 条的封顶是盲目的——合在一起，
"无限循环"在结构和运行两个层面都被堵死。这正是 **A11** 断言的内容：

> **A11：图必能终止。** 静态：无出口的环被校验拒收、有环必有显式上限；
> 动态：构造一个永不收敛的环（裁决模型永远要求返工），断言运行被
> `max_iterations` 拦停且账本记了 GuardViolation（v1 已有此测试，纳入断言）。

### 4.3 成本守卫按 Quorum 的两道查改造

现在只在节点开始前查一次。改成：

- 派发前：`已花 + 本次预估 > 上限` 就停（不是 `已花 > 上限`，后者等于允许最后一次无限超支）
- 节点完成后：`已花 > 上限` 立即停止后续派发

`coding_agent` 的预估不按 prompt 长度算，按每次调用一个固定额度算。
Quorum 有 9 个样本证明 prompt 长度不是成本的预测因子（1583 字符的 prompt 跑出过
118 万 token），会话深度才是。

### 4.4 闸门

A1–A7 照旧 + A9（每个参数都验证生效）+ A11（图能终止）+ 多入口/扇入各跑通一次。

## 5. M5：界面重做

> **判断修正记录（2026-08-16）**：本节初版把界面定位为"动效克制的工程工具台"，
> 动效强度给到 3/10。主人不认可：**美观高级是一等目标，不是工程保守主义的附属品**。
> 修正后的取向写在下面。保留不变的只有一条铁律：**清晰是前提**——任何视觉决策
> 如果让"看清每个节点的输入输出与完整性"变难，它就是错的。

**设计定位：一句话说清我要做什么。**

> 一个**精致、有光泽、有动感**的现代深色界面：Linear 的细节精度、
> Arc 的玻璃质感与动效愉悦感、Raycast 的键盘优先气质、Geist 的排版系统。
> 高级感来自精确的设计系统与有目的的动效编排，不是堆装饰。
> 打开它的第一眼应该是"这个工具很贵"，用起来应该处处顺手。

三个刻度（taste 的说法）：视觉密度 6（信息要密，但用层次组织得优雅，
不挤）、动效强度 7（丰富的、有物理感的、全部说得出理由的动效）、
布局变化度 5（工具界面可预测，但允许面板浮动与嵌套的层次变化）。

### 5.1 设计语言（具体到实施不跑偏）

**表面与材质（高级感的第一来源）：**
- 多层暗色表面体系：画布 → 面板 → 卡片 → 悬浮层，四层各有固定的亮度和边框值，
  层次一眼可读；不使用纯黑，最深用带蓝调的近黑
- **渐变描边**：卡片与面板的 1px 边框用"顶部亮、底部暗"的垂直渐变，
  模拟受光——这是 Linear/Arc 级质感的最低成本来源
- **玻璃面板**：顶栏、详情抽屉、悬浮卡片用 `backdrop-blur` + 半透明底 +
  1px 内描边高光；提供 `prefers-reduced-transparency` 的实底降级
- **微噪点纹理**：固定层、`pointer-events-none`、约 2% 不透明度，消除大面积
  渐变的色带感

**色彩：**
- 语义色带光泽：运行中 / 完成 / 失败 / **降级** / **截断** 各有固定色相，
  状态填充用微渐变 + 状态色边缘光，而不是平涂——降级与截断必须显眼，
  它们是 v1 花真钱换来的教训
- 一个强调色锁死全页，用于：运行按钮、当前选中、品牌感点缀；允许强调色的
  光谱渐变（同色相浅→深）用在标题光效和运行态光环上，不引入第二色相
- 禁：AI 紫渐变、无语义的霓虹发光、纯黑纯白

**排版与图形：**
- Geist + Geist Mono；所有数字 `tabular-nums` 等宽——观测台的数字在跳动，
  宽度不许抖
- 严格字号阶梯（12/13/15/18/22/28）与 8pt 间距网格；小型大写标签
  （`letter-spacing` 0.08em）用于分组标题
- 图标 Phosphor 一族，统一 `strokeWidth`；一套圆角系统（卡片 12 / 控件 8 /
  徽章全圆）锁死全页

**动效（每个都说得出表达什么，spring 物理，禁线性缓动）：**

| 动效 | 表达什么 |
|---|---|
| 页面入场：侧栏 → 画布 → 面板按 60ms 阶梯浮现 | 空间的建立，一次看完结构 |
| 运行中节点的呼吸光环（缓慢、同色相） | 活着，正在工作 |
| 活动边上的流动虚线/粒子 | 数据正在流动，方向可见 |
| 节点完成：对勾以 spring 缩放落定 | 一段工作的确定性收束 |
| 失败：红色单次脉冲后保持 | 出事了，但不是持续的噪音 |
| 新事件从事件流顶部滑入、旧事件下移 | 时间的方向 |
| token / 成本数字 count-up 滚动 | 累积感，钱在花 |
| 抽屉滑入、hover 时卡片 1px 上浮 + 边框亮起 | 层次与可点击性 |
- 全部动效遵守 `prefers-reduced-motion` 降级为静态；不布置纯装饰的无限循环

**其他：**
- 空状态与骨架屏精心设计（骨架匹配最终布局，不用通用转圈）；加载有进度感
- 焦点环、选中文本色、滚动条、tooltip 全部定制，不留系统默认
- 顶栏统计加 sparkline（token 随时间的迷你曲线），成本与耗时用等宽大数字
- 暗色为主、浅色同步做；对比度过 WCAG AA；技术基底 Tailwind v4 + CSS 变量
  语义色 + Motion 动效库

### 5.2 功能性的改进（清晰的骨架，视觉长在它上面）

这几条是"展示清楚"的本体，任何皮肤都不能替代：
