# Changelog

All notable changes to Atlas are documented here. The format follows Keep a Changelog and versions follow Semantic Versioning.

## Unreleased

### Added
- Browser-matrix GUI smoke, step one (E-4): a Playwright chromium e2e suite under `e2e/` with zero real provider calls — the suite's server fixture (`e2e/helpers/server.py`) assembles the same `atlas.web.create_app` the product uses with a `FakeProvider`-only registry factory and seeds two genuinely executed runs into a temporary runs root: one routed human-gate run paused at the approval panel (approving resumes it through the same engine path a real approval takes), and one completed run whose ledger timestamps and durations are normalized to fixed values so the finale card renders byte-stable across invocations. The keyboard test walks the real Tab ring and asserts the approval controls are reachable in DOM order (comment input → approve → request changes → reject), that focus is visibly indicated (the input's designed box-shadow ring, buttons' ≥2px outline), and that Enter on the focused approve button is equivalent to clicking it — the run completes and the finale card renders; selectors are role/text/aria only, `mouse.*` never appears, and no `nth()`. A finale-card baseline screenshot is committed under `e2e/__screenshots__/` with locale, timezone, and reduced-motion pinned so two consecutive runs must match — the flake rule is root-cause fixing, never tolerance tuning (reverse-verified: disabling the focus outline, renaming the input's aria-label, and changing the card's padding each turn the corresponding test red). The suite runs in a dedicated optional workflow (`e2e-smoke.yml`, `workflow_dispatch` + release trigger) clearly named apart from the main CI gate. Also in this batch: `fold_events` gained the explicit `search_performed` no-op branch that E-1's explicit-ignore discipline required (behavior unchanged; the strip-regression lock stays green).
- Release bundle with a prebuilt frontend (E-3): the release workflow now also ships a bundle zip — a clean code tree from `git archive` (tracked files only, so gitignored credentials and run records are excluded by construction) with the built `web/dist` overlaid and a `manifest.json` (frontend digest, git sha, build time, node version) written by the same function the runtime uses, so the packager's hash and the startup hash cannot drift. Exclusion enforcement is machine-checked twice — over the staging tree and again over the unzipped content — with the checker living in `atlas/distbundle.py` where it is unit-tested: tracked secrets, run directories, cache dirs, and key material fail the job with the offending paths. `atlas-web` resolves the dist through four levels (CLI `--dist` > `ATLAS_WEB_DIST` > repo-sibling `web/dist` > in-package `web-dist`), fails loud with all four candidates and three remedies when none has an `index.html`, and treats a manifest digest mismatch as a loud stderr warning in local development while the new CI smoke job asserts equality (same function, both call sides tested) and probes that `/`, `/api/*`, and `/mcp` routes survive the static mount. Git still does not track `web/dist`.
- Agent collect — multi-name collection from agent work directories (E-2B): `config/agents.json` runner config may declare a read-only collect list, and after a successful CLI run the execution directory (the coding-agent worktree, or the runner-reported temp directory for research) is scanned by relative glob and every matched file is stored write-once as an extra artifact appended to `node_done.artifacts` in relative-path lexicographic order. Collection is a closed, audited contract: `role` is restricted to `output|raw|report` (the diff stays with the system diff collector; `error/changes/input` are not open); patterns must be relative with no `..`, absolute paths, or backslashes; symlink/junction entries are refused rather than followed; the system-excluded directories can be extended via `collect_exclude_dirs` but never shrunk; hard caps of 20 files, 16 MiB per file (the artifact cap), and 64 MiB total fail the node as a governance error carrying counts and bytes in the message — a partial collect masquerading as complete is worse than failing, so lists are never silently truncated, and two relative paths that sanitize to the same logical name fail loudly instead of silently shadowing each other. Logical names are `{name_prefix}.{sanitized relative path}` with separators and dots folded to hyphens and unicode letters preserved (CJK filenames work; non-ASCII names are viewable and approvable but the ASCII-only bare-name consume check cannot reference them — an honest limitation). Collection is local_cli-only, adds no model cost, replays through `node_done` like any other artifact, is consumable downstream by bare logical name, and a runner that reports no execution directory skips collection with a loud ledger note instead of pretending. Motivation: a coding agent changing ten files previously produced one merged diff that downstream approval and branching could not target at file granularity, and research artifacts survived only as the model's own paraphrase.
- Run attachments (E-2A): bring your own materials into a graph without pasting them into the task text. `atlas_run_workflow` (MCP) and the Web run endpoint accept `attachments: [{name, path}]` where `path` is an absolute local file read once at admission. Names are the consumed logical names — lowercase ASCII only (`^[a-z][a-z0-9_.-]{1,63}$`; uppercase variants like `Task` and look-alike unicode are rejected by design), reserved suffixes `.output/.diff/.error/.changes` refused, `task` and node-id collisions refused. Admission is two-phase: every attachment is read, size-checked (≤16 MiB each, ≤32 MiB total), and hashed before a run id exists — any failure rejects the whole start with no run directory and no partial copies; the passing set is then byte-cloned into the run's write-once artifact store (atomic temp+fsync+rename with post-copy hash re-verification, cleanup on failure), so there is never a run with half its attachments and the source file is never referenced again. The ledger records `attachment_admitted` (name/sha256/bytes/basename — never the source path, and responses never echo it) right after `run_started`; `fold_events` explicitly ignores the event (strip-regression locked). Downstream nodes consume attachments by bare logical name — the graph validator admits bare names under the attachment charset while still rejecting `<typo>.output`-style wiring mistakes at load time — and projections carry only a summary line (name · size · sha256 prefix) instead of inlining up-to-16-MiB bytes, keeping big inputs out of the prompt budget; original bytes open in the artifact workspace and approval panels show them naturally. Fork interaction stays honest: a node consuming an attachment cannot statically prove input equality across runs, so it conservatively re-runs, while nodes not touching attachments are unaffected. Tool count stays at eight (`attachments` is a parameter).
- Closed `search` node type (E-1): web research as a first-class, fully audited graph node. Atlas hosts pluggable backends itself — closed enum `backend: tavily` (needs `TAVILY_API_KEY`) or `searxng` (needs `ATLAS_SEARXNG_BASE_URL`), with missing configuration rejected at the same preflight position as model credentials (dry-run surfaces it too), and a `model` field on a search node is refused at validation (there is no model to help). Query sources follow a three-level priority: explicit `queries` (≤5, over-cap rejected at validation), an upstream artifact whose JSON carries a top-level `queries` array (truncated to 5 with `truncated_queries` recorded in the ledger), or the whole prompt as a single query. Every execution lands a `search_performed` event (backend, queries, result count, duration, per-result url/title) plus a write-once JSON artifact; `cost_usd` is the backend's reported cost or null — never a fabricated $0 — and with `max_cost_usd` set the dispatch conservatively reserves the remaining budget up front, settling unknown actuals conservatively like agent nodes. Search results are untrusted content and prompt-injection is treated as a real attack surface: downstream consumption projections fence them inside `<untrusted-source>` with a system-level note, closing tags inside page content are escaped (`<\/untrusted-source>`) so the fence cannot be closed early (byte-level positive/negative tests, plus a fixed injection sample asserting routing and terminal state stay unaffected), and domain filters resolve the URL host properly so `https://arxiv.org@evil.com/` filters as evil.com — while redirects/shorteners are honestly documented as never followed. Backend network/HTTP failures classify as content failures (usable with `on_error: stop|continue|branch` and the `<node>.error` artifact); cancellation is consumed at every query boundary; node `timeout_s` covers the whole query batch; the heartbeat window opens per query. Search artifacts never enter P7 skip candidates or P13 synthesized imports — reusing stale search results as fresh execution would be fraud — and explicit imports carry the untrusted marker so the fence survives the copy. Motivation: the only prior internet path was the agent CLI's black-box web tools (no ledger events, no budget visibility, no auditable sources), which conflicts with Atlas's ledger-as-only-truth principle. HTTP uses the standard library; no new runtime dependency.
- Three-way approval with routed request_changes (P11). Human nodes gained `approval_mode: binary | routed` (default binary - old graphs keep byte-identical fingerprints and behavior); routed mode unlocks the third decision `request_changes`, which requires a non-empty comment and routes along a validation-mandated reserved edge `when: __changes__` back to a revision node, consuming `guards.max_iterations` exactly like any other bounded loop. All three decisions pass through the same locked `_verify_approval_material` chain (projection hash, consumed artifacts, diff digests cross-checked against projection evidence) before anything is persisted, and a binary graph that is handed a `request_changes` refuses it loudly before any event is written. The validator lives in one domain function (`validate_approval_decision`) shared by the engine, the Web endpoint, and MCP surfaces; the Web approval panel shows the third button only for routed gates. The requested changes land as a write-once `<node>.changes` artifact (role `changes`, new closed-registry entry) that revision nodes consume explicitly, and an approve overwrites the per-node route fact so a later approve never gets re-routed by a stale request-changes marker (the same merge-only-map lesson P3 taught).
- Run retention, star protection, and a listing index (P10). Two opt-in environment variables — `ATLAS_RETENTION_MAX_RUNS` and `ATLAS_RETENTION_MAX_AGE_DAYS`, both unset by default so nothing is ever auto-deleted — drive a sweep that runs after each graph execution finishes (and is callable directly): candidate selection is a pure function over the runs root that admits only persisted `done`/`failed`/`cancelled` runs without a star marker, with `running`/`paused`/`interrupted`, starred runs, live controllers, and runs lacking a ledger start timestamp all protected; the count quota keeps the newest N of that eligible pool (protected runs never consume quota), the age threshold cuts strictly older ones, and both criteria union. Deletion goes through one shared executor (`atlas/runs.py::isolate_and_delete_run`) also now behind the Web DELETE endpoint: stable run lock held throughout, same-volume rename into `.trash`, symlink/junction-proof cleanup (never follows links out of the run directory), tombstone leftovers retried by re-invocation rather than resurrected — and star-marked runs are refused even when terminal. Starring (`POST /api/runs/{id}/star`, write-once with an optional note; no un-star API by design — removing the marker file is a deliberate manual act) works on any run including running ones; the runs list carries a `star` flag. A lightweight index (`.runs-index.json`, keyed by run id with a size+mtime fingerprint of each ledger) accelerates run listings: fingerprint match serves the cached fold result, any change re-reads just that ledger, deleted runs are pruned against a full membership scan (never pagination fragments), corruption is loudly discarded and rebuilt, and the dynamic interrupted liveness probe always bypasses the cache. Listing output is byte-identical to the full-fold path (contract-tested both ways). Deletion-failure accounting propagates as loud stderr notes without ever failing the run that triggered the sweep.
- Fork and invalidation closure (P13). A graph can declare `fork: {run: <id>}` to re-run a (usually edited) graph from a stable-terminal source run, recomputing only what actually changed: Atlas replays both sides' invocation identities (the P7 digest over execution fields, prompt, ordered input hashes, and backend identity — task hashes and unchanged-upstream output hashes are statically resolvable from the source ledger), marks every node whose identity cannot be proven equal as changed, and computes the invalidation closure as changed + all static-graph descendants (conditional edges count — any possible data flow invalidates; loops invalidate wholesale per strongly-connected component, no intra-loop partial retention; a join that depends on a changed branch therefore always re-runs — you cannot pin everything and accidentally skip the target node). Nodes inside the closure may not declare `imports` (contradiction rejected loudly before any run directory is created); nodes outside the closure with event-proven complete artifacts get synthesized imports that flow through the exact same P7 admission chain (source stable lock, provenance verification, atomic byte copy, runtime re-verification) and the same skip gates. The plan is fully accounted: `fork_planned` records changed/closure/import map/algorithm version (`p13-fork-v1`) right after `run_started` (which carries `fork_source_run` + `fork_plan_sha256`), `fork.run` enters the spec fingerprint (unforked graphs keep byte-identical fingerprints), dry-run shows "what will rerun vs. what will be copied from which run", and `fold_events` ignores the new event type (strip-regression locked). Verified across all five graph shapes (linear, parallel, join, conditional, loop) plus failed/paused sources reusing only event-proven artifacts.
- Skip-time input re-verification (closes a P7 gap found while designing P13). The static skip plan's input hashes are a prediction made from imported clones; if the same logical name's producer actually re-executes and overwrites the state entry with different bytes, the prediction is stale. Reused nodes now recompute their input hashes from the live state before emitting `node_imported_reused` and delegate to real execution on mismatch (reverse-verified: with the check disabled, a conditional-router graph with changed upstream bytes silently skipped its consumer). Deterministic producers that re-emit identical bytes still legitimately reuse — hash equality is byte equality.
- Artifact-import lookup now verifies the event's node is the artifact's producer (P7 fix exposed by P13's multi-node-source tests): the fallback branch of the latest-artifact scan previously matched any `node_done` for any `.output`-suffixed logical name, so importing an early producer's output from a multi-node source silently copied a later node's bytes (single-node-source tests never hit it; regression-locked both directions).
- Invocation inputs now enter the digest in `consumes` list order (`p7-invocation-v3`) instead of sorted by logical name: `build_projection` inlines upstream bytes in that same order, so `[task, a.output]` and `[a.output, task]` are different projection layouts of one prompt — genuinely different executions whose results should not be substituted for each other (reviewer suggestion from the P7 batch, adopted 2026-08-27). Recorded invocations under older algorithm versions stay interpretable on their own terms; equality simply requires the same version, so cross-run auto-skip conservatively declines across version boundaries.
- Artifact import and invocation identity (P7). A node can declare `imports: [{run, name}]` to reuse an expensive upstream result from a stable-terminal run: at admission Atlas holds each source run's stable lock, verifies the ledger's latest provenance for the logical name, byte-copies the artifact into the new run's write-once store (temp file + fsync + atomic rename, so a mid-copy kill leaves no partial artifact; a post-copy hash re-verification catches in-lock drift), and records an `artifact_imported` lineage event (source run/name/hash, new path/hash, algorithm version). Every LLM dispatch now writes its `invocation_sha256` on `node_started` — a versioned digest over the node's execution fields (model chain, sampling parameters, and the output-schema acceptance criteria — a stricter `required` list is a different invocation, since the same model response could newly fail validation), effective prompt, ordered input hashes, and the prepared backend identity. When the displaced node's locally recomputed invocation equals the source ledger's recorded value exactly (and the node is an unconditional-edge `stop`-strategy LLM whose consumes are all statically satisfiable), execution is skipped with a zero-cost `node_imported_reused` event; any change to prompt, model, parameters, task, or inputs defeats reuse. Deleting the source run after import leaves the new run fully functional — clones live inside the new run's directory, never as cross-run path references. Imports enter the spec fingerprint (old graphs byte-identical), appear in dry-run renders ("what will be copied from which run"), and missing/running sources fail admission before any run directory is created; a source lock held by a concurrent controller fails deterministically instead of waiting. `fold_events` ignores both new event types (strip-regression locked).
### Added
- Experience-debt small-batch (E). The Web cost bar now shows outstanding reserved budget (`$X*` with a tooltip explaining pre-dispatch reservation semantics) next to actual cost; the run list polls every 20 s so runs started from MCP or another tab appear without manual reload; the event stream got a "查看完整账本" link downloading the full append-only `events.jsonl` via a new `GET /api/runs/{id}/events.jsonl` endpoint (path-traversal-safe, missing-run → 404); the Settings page gained a read-only agents.json status card — file absent / runner disabled shows fail-closed wording, `local_cli` runs the real production preflight and reports CLI version or the exact failure reason — configuration still happens in the file, and responses never contain credential values. Parameters are now honestly checkable: providers that echo request parameters back get `temperature`/`seed` compared against what was sent (`echo_ok` / `mismatch(sent=..,got=..)`), non-echoing gateways are labeled `not_echoed` — the verdict lands on `node_done` (`param_audit`) and renders in the node detail view. The Claude `--help` contract probe failure now names the detected CLI version and both plausible causes (outdated CLI vs changed help layout) instead of only ordering an upgrade. `_resume_graph_replay` (non-product replay bypassing interrupted admission) loudly refuses to run without an explicit `_test_only=True`, and `_NODE_FACTORIES` became the single node dispatch table (research/coding_agent None placeholders removed).
 The Web run page gains a cancel button (visible while a run is running or waiting for approval) behind an explicit confirm dialog that states the request is irrevocable; the `POST /api/runs/{id}/cancel` endpoint now has its own HTTP contract tests (403 without the `X-Atlas-Request` header, 404 unknown run, 409 terminal conflict, cancelled-directly response for paused runs). The `local_cli` runner now terminates the CLI's whole process tree when a cancellation request arrives mid-flight: a watcher polls the request file every 0.2 s, kills the tree (Windows `taskkill /T /F`, POSIX `killpg`; descendant-kill proven by a real subprocess test where a surviving grandchild would leave a marker file), and the node ends as `run_cancelled` instead of silently finishing. A failed tree kill stays a loud `AgentCliError` — failure to terminate is never swallowed into a cancelled state. This extends P2's original semantics: SDK-backed model calls still finish their current attempt, only `local_cli` agent executions get hard tree termination. The budget-mapping path completed its guard matrix: spending-budget exhaustion (`max_budget_usd <= 0`) fails before any process spawns; valid mapping, missing-flag preflight rejection, and overspend reporting were already test-locked.
- Exception taxonomy and node-level `on_error` (P3). A new classification layer (`atlas/exc.py`) splits node-boundary failures into governance exceptions — cost guards, loop guards, cancellation, run deadline, spec/wiring/routing, integrity, ledger limits, approval rejection, run-lock conflicts, and every unregistered type (fail-closed) — that no strategy may ever swallow, and content failures (all candidates failed, which covers fake-success exhaustion and candidate-timeout exhaustion) that graph authors can now strategize per node with `on_error: stop | continue | branch`. Default `stop` keeps old graphs byte-identical in behavior, and default values stay out of the spec fingerprint so existing run identities are untouched. `branch` routes soft failures along the reserved edge key `__failed__` (validation-time requirement, at most one such edge per source, allowed to coexist with the success path's unconditional or conditional edges); `continue` is rejected on nodes with conditional outgoing edges (a soft failure has no output, routing would be undecidable); downstream nodes may consume `<branch-node>.error`. A soft failure writes a write-once JSON error artifact (error class, original exception, per-attempt reasons) plus a `node_failed_soft` event; `fold_events` explicitly ignores that event (strip-regression locked) so terminal semantics are identical with or without it. Routing decisions read a per-node latest-outcome fact channel (`route_facts`: success and soft failure each overwrite their own key, persisted through the checkpoint, re-derived identically on resume) — never the mere presence of a stale `.error` artifact, which cannot be cleared from the merge-only artifact map and would mis-route a branch node to `__failed__` again after it succeeds on re-entry (review blocker 2026-08-26; regression test: fail → handler back-edge → succeed must finish done via the success route). `AgentCliError` is classified separately with an empty soft-fail whitelist — baseline/diff/security errors stay governance. Web and MCP serve the same soft-failure view (status `failed_soft`, error class, error artifact entry) and dry-run lists every non-default `on_error` node.
- Execution finale view and opt-in summary node (S1, user-decided 2026-08-23; no offline report export). Every terminal run (done/failed/cancelled) now shows a zero-cost finale card at the top of the Web run page, derived purely from the event ledger: per-node one-line recaps (model, duration, tokens, cost, output first paragraph), a proportional duration bar, and run start/finish timestamps — no LLM involved, and Web `/api/runs/{id}` and MCP `atlas_get_run` serve the same `finale` object from one builder (`atlas/runs.py::build_finale`). On top of that, a graph-level `summary: {model, prompt_hint?}` (default off, semantic field — it enters the spec fingerprint and snapshot) adds one summarizer call before `run_done`: the prompt is assembled from the ledger (node recaps, task digest, optional user hint), the call is budgeted through the same CostLedger (`cost_reserved`/`cost_settled` under pseudo-node `run_summary`, `max_cost_usd` enforced), covered by the P9 heartbeat, and its output lands as a write-once `run_summary.txt` artifact with a `run_summary_written` event (model/usage/sha256) — hash re-verifiable. Any failure, including budget exhaustion, records `run_summary_failed` and leaves the run's terminal state untouched; the summary text is always labeled "LLM 叙述,事实以账本为准" and dry-run lists the upcoming summary call (model, one estimated call) with its unknown-rate warning joining the existing candidates. `fold_events` explicitly ignores both new event types (strip-regression test locked); a crash between artifact write and event emit replays without double-spending.
- Controller heartbeat (P9). During every in-flight model or agent-CLI dispatch the controller writes `node_progress` events (node, iteration, attempt, candidate model, controller elapsed_ms, phase `waiting`/`retry`) at a run-level interval: default and floor 30 seconds, configurable through `ATLAS_NODE_HEARTBEAT_INTERVAL_S`; values below the floor are rejected loudly instead of clamped. The heartbeat says only that the Atlas controller is still waiting for the call to return — it never claims model-internal progress or percentages (the wording boundary is test-locked: the heartbeat field set is the entire vocabulary). Dispatch windows close at attempt end, transport-failure give-up, unexpected exceptions, cancellation, and terminal state; the close joins the heartbeat thread, so late ticks are rejected and no heartbeat can appear after `run_done`/`run_failed`/`run_cancelled` — verified with a frozen-provider run and a cancel-mid-run run, plus a unit test on the late-tick contract. `fold_events` explicitly ignores the type and a regression test asserts that stripping every heartbeat changes the folded state by nothing. Capacity is counted honestly: at the 30-second cadence one node emits ≈2880 events per day against the 16 MiB ledger cap, so long-running graphs carry a real ledger cost until P10's segmented-ledger governance lands. The same-model transport-retry wait and the agent retry backoff flip the phase to `retry`; agent heartbeats carry the runner name, and SSE/Web show the events as they flow through the ledger.
- Cooperative cancellation (P2). `atlas_cancel_run` (MCP, eighth tool) and `POST /api/runs/{id}/cancel` (Web API; the page-side button ships in this same unreleased cycle — see the D entry below) write an atomic create-if-absent request file without waiting on the controller lock. A running controller consumes the request at llm/human/agent node entry, candidate switch, and transport-retry waits (interruptible sleep), then writes the single `run_cancelled` terminal event; in-flight SDK model calls run to completion (the `local_cli` agent backend later gained whole-process-tree termination on cancel within this same unreleased cycle — see the D entry below). Requests are not revocable: if the controller dies after a request, resume consumes it at the first node boundary. Paused/interrupted runs are cancelled directly under the run lock by the cancel entry (sole writer). `cancelled` is a replayable terminal status: resume and approval reject it, deletion accepts it, repeat cancels conflict, and pending cost reservations stay conservatively accounted. Tool surface is now eight tools. An RFC draft (`docs/rfcs/agent-retry-budget.md`) records the agent-retry budget decision path; no default behavior changed. Also removed the legacy seed-byte write on OS lock files (init and run locks): a concurrent process's write could hit the byte another process had just locked, the recurring `PermissionError [Errno 13]` CI flake; region locks work on empty files and the seed was never read.
- MCP grows to seven tools (P4). `atlas_list_runs(limit, cursor)` lists runs newest-first with stable cursor pagination and the same closed status set, sharing the run-summary builder with the Web list. `atlas_run_workflow(wait=false)` returns `run_id`/`status: starting` right after full preflight, execution-identity assertion and run-lock admission, then a registered background controller executes the graph — long tasks no longer block the MCP session (`wait=false` is mutually exclusive with `persist_as`; default synchronous `wait=true` is unchanged). Web start/resume/approval continuations now run through the same in-process launcher registry (one controller per run; the ledger remains the single source of truth for status).
- Dry-run now returns a `warnings` list (advisory only, admission stays fail-closed): reasoning-capable candidates whose effective `max_output_tokens` (node > provider `maxOutputTokens` > 8192) is below 16384 are flagged — hidden thinking burns the output budget (the 2026-08-22 real truncation); and when `max_cost_usd` is set while any billable candidate (including fallbacks) has unknown pricing, dry-run states that the guard will only admit the first billable node (run `20260822-113908-531dab`). Only probed capability data warns; unprobed models stay silent.
- Lenient JSON extraction (B1): when strict JSON parsing fails on a node with required fields, Atlas strips markdown code fences and extracts the outermost balanced JSON object; if all required fields survive, the same response is accepted with an `output_json_recovered` event instead of burning a fallback candidate, and artifacts still store the raw bytes. Conditional routers read artifacts through the same extraction so routing graphs keep completing. Missing fields after recovery, empty output, truncation sentinels, and output caps still fail exactly as before.
- `atlas-web` serves the MCP tool surface over streamable-http at `/mcp`, so harnesses can connect by URL instead of a stdio subprocess; the stdio entry point is unchanged.
- `atlas_run_workflow` accepts a full custom graph as `yaml` text (ad-hoc run, nothing written) and can solidify it into `workflows/` after a real run via `persist_as`, reusing the same validation and anti-overwrite contract.
- Workflows can be deleted from the Web UI; `atlas_validate_workflow` echoes `file_sha256` so agents can do a read-modify-write loop through `atlas_save_workflow`.
- Paused human gates now show a review-materials panel in the Web UI: the artifacts the gate consumes and the full approval projection, each with its SHA-256, openable in the artifact workspace.
- Rejecting a human gate now requires a reason, enforced synchronously by both the Web UI and the API (`400` before any run lock is touched); approvals may still omit a comment.

### Changed
- Agent retry defaults are now a documented product promise, not an implementation accident: `research`/`coding_agent` nodes never auto-rerun by default (`retry` defaults to 0), and any graph that explicitly declares `retry: N` on an agent node now earns a mandatory dry-run amplification-risk warning (merged into one list-style warning across hits). The warning always states the rerun count, distinguishes cost-constraint presence (no `max_cost_usd` means no total constraint at all; with a cap, CLI-session spend bypasses the pricing table, budget is consumed conservatively per dispatch, and the provider's actual bill staying under the cap cannot be proven), and suggests structural alternatives instead. It is advisory only — nothing is blocked, and llm nodes with `retry > 0` deliberately stay silent (a single API retry is cheap; warning there would dilute attention). Motivation and evidence: the 2026-08-19 stage-D incident where a Kiro agent's first attempt self-reported ~$10.508 and the automatic retry started a second full-cost pass before a human killed the run. Decision record: option A (documented retry=0 promise) plus option C (dry-run warning) adopted, option B (admission hard-block) rejected — see the resolution section of [`docs/rfcs/agent-retry-budget.md`](docs/rfcs/agent-retry-budget.md). The same warning data now flows to the Web preview endpoint (`/api/workflows/{id}/preview`) from the shared builder, so MCP and Web cannot drift.
- The repo-root `.mcp.json` now points to the HTTP endpoint (`http://127.0.0.1:8321/mcp`) instead of launching a stdio child via `uv --directory .`: a shipped relative directory breaks in any harness that spawns the subprocess outside the repo (field-proven with ZCode on 2026-08-23), and a stdio child never shares code with the running `atlas-web`. stdio remains an explicitly documented alternative with an absolute path (`docs/mcp.md` Option 2); README, in-app guides, and the docs contract tests were updated to match.
- Rewrote the READMEs around real runs: the shipped example YAML with its actual ledgered cost, honest failure cases from the run matrix, and measured capability boundaries.
- Renamed the shipped loop example's claim from "repair loop" to bounded retry: back edges re-run a node with the same static `consumes`, so reviewer feedback does not reach the revised node. The example YAML, in-app guide, and skill now say this explicitly; a feedback-carrying loop design is recorded in `docs/BACKLOG.md`.

### Fixed
- Agent CLI preflight now accepts real `claude --help` output; a double-escaped regex class previously rejected flags followed by ordinary spaces/descriptions.
- Agent child processes use an isolated empty `CLAUDE_CONFIG_DIR`, preventing user settings from overriding the selected endpoint and credential. The temporary directory is removed after each call.
- Shipped in-app guides point to the project `.mcp.json` and README rather than local development-only `docs/mcp.md`.

### Security
- Web access remains loopback-only.
- Active credentials, runtime configuration, and run evidence are excluded from source artifacts and scanned release surfaces.
- Missing agent configuration and unmet agent preflight requirements fail closed before run creation.
- Coding-agent work-directory copying is staging, not an OS sandbox: Claude CLI is a same-user process and Atlas does not write the original directory. Atlas compares frozen baseline/result ordinary-file bytes to generate the textual unified diff without Git post-processing, fails loudly on binary changes, and binds approval to baseline/result/patch digests.
- Agent environments contain required system variables plus the selected provider endpoint and credential. `allow_web` controls WebSearch/WebFetch, not OS-level network access.

### Known limitations
- Source distribution only; no PyPI package or prebuilt installer.
- Windows 10/11 x64 is the supported runtime. No Linux/macOS support promise.
- Production agent execution requires explicit `runner: local_cli`, Claude Code 2.1.0+, an agent-model provider with `anthropicBaseUrl`, and a configured credential.
- Agent execution is not OS-sandboxed; coding Bash may access the network even when `allow_web` is false.
- Claude CLI does not enforce Atlas `max_turns`; deadlines and effective budgets are the hard limits.
- Model aliases, reasoning controls, usage, prices, and seed behavior depend on local configuration and provider behavior.
- Multi-user, cloud-hosted, and network-exposed deployments are unsupported.
