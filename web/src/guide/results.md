# 运行结果与数据留存

节点状态包括等待、运行、完成、暂停、失败与软失败（内容失败后图按 `on_error` 继续，带错误类与错误产物入口）。降级表示实际应答模型不是首选模型；应同时查看失败尝试、最终模型和结构校验结果。

run 到终态（完成/失败/取消）后，运行页顶部出现终局卡片：每个节点的一句话回顾（模型/耗时/token/成本与输出首段）、时间线与成本条，全部由事件账本派生，不调用模型。配置了图级 `summary` 的 run 还会多一段总结：run 结束前由指定模型回顾各节点工作，产物与成本进账本；总结失败只记事件，不影响 run 终态。总结文本是 LLM 叙述，事实以账本为准。

完整输入是节点实际消费的投影；输出、报告、diff 和哈希状态是运行证据。启用生产 runner 后，真实的 research/coding agent run 可生成报告；可写 coding agent 还可生成基于冻结 baseline 与结果字节清单的完整文本 diff。dry-run 不执行 agent，只展示将运行的结构与绑定，不能当作执行结果。哈希通过只证明记录的字节未静默变化，不证明报告、diff 或结论本身正确。

`runs/<run-id>` 可能包含完整任务、prompt、源码、模型输出、diff、哈希和人工决定。它默认被 Git 忽略，但未加密、未自动脱敏、也没有自动保留期。分享、备份或删除前应按数据敏感性人工处理。
